Payments are linked to verified delivery milestones. Each milestone has clear acceptance criteria that must be met before payment is released.

|---|-----------|-------------|:----------:|---------------------|
| P1 | Discovery Complete | Confirmed backlog, architecture, environments ready | 10% | Requirements meeting held; FAT pipeline operational |
| P2 | MVP Delivered | IAAS application form (9 sections) deployed to FAT | 20% | Application can be created, submitted, and viewed in admin |
| P3 | Integrations & P2 Fix | Credit check, postcode, cross-system checks; P2 resolved | 20% | All integrations return data; P2 fix in production |
| P4 | RBAC & Admin | 500 users, role management, reporting | 15% | Admin portal functional with user/org management |
| P5 | UAT Entry | All features deployed to UAT | 15% | UAT environment provisioned with full feature set |
| P6 | Production Release | Live deployment + handover | 15% | Production live; handover documentation accepted |
| P7 | Hypercare Complete | 4-week support period | 5% | No outstanding P1/P2 defects; support period concluded |

## 3. Justification

### Why milestone-based (not time & materials)?
- **Predictability**: AiB knows total cost upfront
- **Risk transfer**: Supplier bears delivery risk, not AiB
- **Incentive alignment**: Payment only on verified delivery
- **Auditability**: Clear link between spend and outcomes

### Why this distribution?
- **Front-loaded (30% by Week 4)**: Reflects intensive discovery + MVP effort that sets the foundation
- **Mid-weight (50% in Weeks 5-12)**: Bulk development and integration work
- **Back-loaded (20% in Weeks 13-20)**: Ensures supplier stays engaged through deployment and hypercare
- **5% retained for hypercare**: Guarantees post-release support commitment

### Payment conditions
- Each milestone requires **written acceptance** from AiB Delivery Lead
- Invoice raised **after** acceptance confirmation
- Payment terms: 30 days from invoice date
- Disputed milestones: mediation within 5 working days

## 5. Change Control

If scope changes during the SOW:
1. Change request raised by either party
2. Impact assessed (effort, timeline, cost)
3. Approved by AiB before work commences
4. Payment plan adjusted proportionally if material change
5. All changes documented in SOW amendment register
